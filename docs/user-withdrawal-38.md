# 회원 탈퇴 계약

기준은 API v1.12의 4.6·7.8·7.12와 ERD v1.13이다. 현재 V13 마이그레이션은 혼잡도 정밀도·39개 슬롯·ESTIMATED 출처를 확장하며 첨부 명세보다 앞서 있지만, 탈퇴 스키마에는 차이가 없다.

`DELETE /api/v1/users/me`는 Bearer JWT와 숨겨진 `@CurrentUser`로 사용자를 식별한다. 성공은 `200 {"success":true,"data":null}`이다. 비활성 사용자는 기존 `TOKEN_INVALID` 계약을 유지한다. 방 잠금 시간 초과는 `ROOM_BUSY(409)`, 기타 DB 오류는 기존 `INTERNAL_ERROR(500)` 경로로 전달된다.

탈퇴는 하나의 READ COMMITTED 쓰기 트랜잭션이다. 사용자 행의 DB 쓰기 잠금 → 활성 상태 재조회 → DB `room_id ASC` 목록 조회 → 같은 순서로 모든 방 잠금 → 현재 멤버십별 RoomLeaveProcessor 호출 → 사용자 soft delete → 모든 Refresh Token 폐기 → 커밋 순서다. 모든 방 잠금을 얻기 전에 엔티티를 변경하지 않는다. 방과 멤버십이 일반 퇴장으로 이미 사라졌으면 건너뛰지만 무결성 오류와 잠금 실패는 전파하며 전체 롤백한다.

사용자 잠금은 생성의 각 REQUIRES_NEW 저장 시도, 참여 저장 트랜잭션, refresh 발급·회전, 명시적 로그인 복구가 공유한다. 잠금 쿼리 뒤 refresh하여 1차 캐시의 과거 deletedAt으로 판단하지 않는다. 생성의 비트랜잭션 재시도 경계는 유지하며 코드 UNIQUE 충돌만 총 5회 시도한다. 외부 트랜잭션에서 사용자 잠금을 잡은 채 생성 시도를 호출하지 않는다. 사용자 잠금에는 새 timeout 정책을 추가하지 않는다. DB 설정에 의한 실패는 ROOM_BUSY로 바꾸지 않는다.

refresh는 토큰의 사용자 식별을 읽은 뒤 사용자 → 토큰 변경 순서를 지킨다. 재사용 감지와 family 폐기는 기존처럼 오류 결과를 반환하여 커밋한다. 탈퇴가 먼저 커밋되면 새 토큰은 발급되지 않고, refresh가 먼저 커밋되면 탈퇴가 그 토큰까지 폐기한다. 카카오 외부 호출은 잠금 밖에서 실행한다. 명시적 로그인만 삭제된 계정을 복구하며 방 멤버십·투표·폐기 토큰은 복구하지 않는다.

닉네임 수정도 사용자 잠금 뒤 활성 상태를 검사한다. 탈퇴 전에 읽은 엔티티의 저장이 deletedAt을 되돌리는 것을 방지한다. 사용자 잠금은 실제 READ COMMITTED 쓰기 트랜잭션인지 확인하며, pending 변경을 flush하거나 지우는 방식으로 잠금 전 변경을 허용하지 않는다.

OWNER 승계는 DB joined_at ASC, id ASC이며 기존 OWNER 삭제·flush 후 승격한다. 마지막 멤버의 방과 연결 기록은 DB cascade로 삭제한다. 탈퇴자의 표는 멤버 FK cascade로 삭제한다. 유지되는 방의 후보·과거 채팅·추천 및 최초 created_by는 보존한다. 사용자 행을 hard delete하지 않는다.

#42·#43은 실제 WS 종료와 방 이벤트 및 SYSTEM 메시지를 연결한다. RoomLeaveProcessor 반환 시점은 커밋 시점이 아니다. immutable payload를 최외곽 탈퇴 트랜잭션의 성공 커밋 후에만 발행한다. 삭제되는 방에는 SYSTEM을 저장하지 않는다.

기존 JWT 체계를 유지하므로 재로그인 복구 후 아직 만료되지 않은 과거 Access Token을 세대별로 구분하지 않는다. 탈퇴 후 복구가 끼어드는 경우 과거 생성·참여 요청과 새 요청도 구분할 수 없다. 이를 차단하려면 토큰·요청 세대 정책을 별도 합의해야 한다. 복구와 토큰 발급은 별도 트랜잭션이므로 사이에 다시 탈퇴하면 로그인 발급은 TOKEN_INVALID로 실패할 수 있다. 이미 인증을 통과해 실행 중인 일반 보호 요청을 소급 취소하지 않는다.
