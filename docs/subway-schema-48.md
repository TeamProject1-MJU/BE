# 지하철 그래프·혼잡도 스키마 (#48)

기준은 ERD v1.13(`docs/erd_v1.13_20261029.dbml.txt`)과 API 명세 v1.12 부록 A다. `V10__create_subway_graph_and_congestion.sql` 하나로 추가하며 V1~V9와 V4의 stations는 변경하지 않는다.

## 테이블

| 테이블 | 역할 | 키·인덱스 |
| --- | --- | --- |
| subway_lines | 노선(코드, 이름, `#RRGGBB` 색, 정렬 순서) | `uq_lines_code (line_code)` |
| station_lines | 그래프 노드 = (역, 노선). 노선 안 순서 seq, 분기 branch_code(기본 `MAIN`) | `uq_sl_station_line (station_id, line_id)`, `uq_sl_line_code (line_id, station_code)`, `uq_sl_line_branch_seq (line_id, branch_code, seq)` |
| station_connections | 방향 있는 간선. RIDE(같은 노선 이동)·TRANSFER(환승) | `uq_conn_from_to (from_station_line_id, to_station_line_id)`, `idx_conn_to (to_station_line_id)` |
| congestion_stats | 노드·방향·요일 유형·30분 슬롯별 혼잡도 | `uq_cong_slot_source (station_line_id, direction, day_type, slot_start, source)` |

PK는 stations와 같은 `bigint generated by default as identity`다. enum 컬럼은 PostgreSQL enum 타입 없이 varchar + CHECK이며, 길이는 허용값 최대 길이(connection_type 8, direction 5, day_type 8, source 9)를 쓴다.

FK는 `fk_sl_station`, `fk_sl_line`, `fk_conn_from`, `fk_conn_to`, `fk_cong_station_line`이다. ERD Ref에 삭제 동작이 없으므로 PostgreSQL 기본값(NO ACTION)을 쓴다. 참조 중인 역·노선·노드는 삭제할 수 없고, 정적 데이터는 다시 적재하는 방식으로 교체한다.

## CHECK 제약 (부록 A 이름 그대로)

| 이름 | 조건 |
| --- | --- |
| ck_lines_color | `color ~ '^#[0-9A-Fa-f]{6}$'` |
| ck_sl_seq | `seq >= 1` |
| ck_conn_not_self | from ≠ to |
| ck_conn_dir | RIDE면 direction 필수, TRANSFER면 direction null |
| ck_conn_nonneg | `travel_seconds > 0 and distance_m >= 0` |
| ck_conn_type | RIDE, TRANSFER |
| ck_conn_direction_val | null 또는 UP, DOWN, INNER, OUTER, LOOP |
| ck_cong_pct | `congestion_pct >= 0` |
| ck_cong_slot | 분이 0 또는 30이고 06:00~23:00 (35개 슬롯) |
| ck_cong_model | PREDICTED일 때만 model_version 있음 |
| ck_cong_level | 단계와 pct 구간 일치: COMFORTABLE [0,35), RELAXED [35,50), NORMAL [50,100), CROWDED [100,150), VERY_CROWDED [150,∞) |
| ck_cong_direction | UP, DOWN, INNER, OUTER, LOOP |
| ck_cong_day | WEEKDAY, SATURDAY, SUNDAY |
| ck_cong_source | PREDICTED, MOCK (ACTUAL 없음) |

congestion_level_label에는 CHECK를 두지 않는다. ERD는 단계에만 "pct와 일치 CHECK"를 적었고, 라벨은 "AI 파일 값 그대로" 저장한다고 적었다. 부록 A에도 라벨 제약은 없다. 라벨과 단계의 대응은 적재 스크립트에서 검증한다.

## 적재 순서

1. subway_lines
2. station_lines (stations는 V4에 이미 있고 먼저 적재되어 있어야 한다)
3. station_connections (RIDE, TRANSFER)
4. congestion_stats

FK 때문에 이 순서를 지켜야 한다. 다시 적재할 때는 역순으로 지운다.

데이터 형태 메모:
- 2호선 순환 닫힘은 seq가 거꾸로 가도 간선의 direction으로 표현한다(충정로(43) → 시청(1) = INNER, 시청 → 충정로 = OUTER).
- 지선(성수지선, 신정지선, 마천지선)은 같은 line_id 안에서 branch_code를 달리하고 seq를 1부터 다시 센다. 분기점 역은 본선 노드 하나만 가진다.
- TRANSFER는 방향별 행이고 A→B와 B→A 값이 다를 수 있다.
- `(line_id, branch_code, seq)` 유니크가 실제 데이터에서 성립하는지는 적재 때 확인한다(명세 15장 확인 항목).

## 명세 부록 A와 ERD의 차이

- **ACTUAL**: ERD v1.13 `congestion_source`와 부록 A `ck_cong_source`는 모두 PREDICTED·MOCK만 허용하므로, 현재 제약 정의 자체는 서로 일치한다. 다만 명세 v1.9 변경 이력에 "ACTUAL·MOCK은 적재 시 같은 기준으로 단계·라벨을 채우고"라는 문구가 남아 있다. v1.12에서 ACTUAL을 사용하지 않기로 했으므로 이 문구는 과거 기준이며, 이번 스키마는 v1.12와 ERD v1.13에 따라 ACTUAL을 거부한다. MOCK은 적재 시 단계·라벨을 채운다.
- ck_cong_slot은 부록 A의 식을 그대로 쓴다. 초 단위는 검사하지 않으므로 `06:00:15`처럼 초가 있는 값은 통과한다. 적재 스크립트는 `HH:MM`만 넣는다.
