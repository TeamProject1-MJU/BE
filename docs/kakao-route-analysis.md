# 카카오 대중교통 경로 API 응답 분석 (#58)

API 명세 15장 #1 확인 항목을 실제 호출로 확인한 결과다. 2026-11-02에 26회 호출했다. 응답 원문은 카카오 정책상 저장하지 않으므로 이 문서에는 필드 구조와 샘플 값만 적는다. 원문은 `scripts/kakao_probe/scratch/`(git 제외)에서만 다뤘다.

> 참고: 이 분석 이후 V12(#67)에서 4호선 `당고개`를 `불암산`으로 변경했다. 아래 본문은 분석 시점(V11) 기준이다.

## 결론

- 엔드포인트가 있고 우리 키로 호출된다. 26회 모두 HTTP 200, `status: OK`.
- SUBWAY 단계의 `stops[]`는 승차역부터 하차역까지 정차역을 빠짐없이 준다. 우리 그래프에서 연속 정차역 쌍은 모두 인접 RIDE 간선이었다(불일치 0).
- 노선명은 `"2호선"` 형식이고 지선 표기는 없다. 방면(headsign)은 없다. 방향은 명세대로 서버가 간선으로 정해야 한다.
- 역명은 괄호 부역명 제거만으로 대부분 맞는다. 지원 범위 안에서 맞지 않은 이름은 **`불암산`(우리 데이터 `당고개`) 하나**였다.
- 4호선 `당고개`는 카카오 표기에 맞춰 `불암산`으로 개명하기로 확정했다(Flyway V12, 별도 이슈). 그 밖에는 괄호 제거로 맞으므로 역 별칭 테이블은 필요하지 않다(아래 "역 별칭 테이블 판단").
- 경로는 `type = SUBWAY`인 것만 쓰고, 없으면 내부 다익스트라(INTERNAL)로 폴백하기로 확정했다(아래 "6.1 규칙 변경 제안").

| 항목 | 값 |

이번 호출은 `input_coord=WGS84`, `output_coord=WGS84`로 하고 출발·도착 좌표는 V11 시드의 역 좌표를 썼다. 출발 시각을 지정하는 파라미터는 문서에 없다.

> #127 추가: 경로 `totalTime`은 단계 `time` 합과 같지 않을 수 있다. 차이는 요청 좌표와 카카오 역 위치 사이의 보정분으로 보며(좌표 이동 실험, 카카오 좌표로 호출하면 차이 0초, 가산성 예측 4/4), 그래서 서버는 `totalTime` 대신 단계 합을 소요시간으로 쓴다. 한계: 검증 역쌍 2개. 또 SUBWAY 단계 `time`은 우리 시각표의 승차역 도착 → 하차역 도착 시간과 같아 승차역 정차 30초가 들어 있고, 카카오맵 앱(승차역 출발 → 하차역 도착)보다 구간이 약 30초 길다(성수를 지나는 2호선 단계는 30초 더, 원인 모름). 정차 시간은 노선마다 30~40초로 달라 고정값으로 빼지 않는다. 카카오 좌표로 호출해도 차이가 남거나 `totalTime`이 단계 합보다 작은 경로가 나오면 이 판단은 틀린 것이다. 자세한 내용은 `docs/route-search-81.md` "카카오 소요시간 = 단계 합 (#127)".

## 확인 항목 (명세 15장 #1)

**1. SUBWAY 단계의 stops[]**: 승차역~하차역 정차역 전체를 준다.
- 방화→하남검단산 49역, 장암→온수 42역, 지축→오금 34역처럼 끝에서 끝까지 모두 나온다.
- 우리 그래프로 매칭된 연속 정차역 쌍이 모두 인접 RIDE 간선이었다(빠진 역 0건). 급행 열차가 포함된 단계도 정차역은 모든 역을 나열한다.

**2. 노선명 형식**: `vehicles[].name`은 `"1호선"`~`"8호선"` 형식이다. `"수도권"` 접두어는 없었다.
- 지선 표기가 없다. 성수지선·신정지선도 `"2호선"`, 마천지선도 `"5호선"`이다. 어느 지선인지는 정차역으로 판단해야 한다.
- `vehicles`에는 같은 노선이 여러 번 나올 수 있다(예: 서울역→청량리 `1호선` 5개, type `일반`×3, `급행`×2). 노선 판정에는 이름만 쓰면 된다.
- 1~8호선 밖 노선명: `경의중앙선`, `수인분당선`, `9호선`, `경춘선`, `신분당선`, `공항철도`.

**3. 역명 표기 차이**
- 괄호 부역명이 많다: `충정로(경기대입구)`, `잠실(송파구청)`, `교대(법원.검찰청)`, `청량리(서울시립대입구)`, `온수(성공회대입구)`, `새절(신사)`, `동대문역사문화공원(DDP)`.
- 4호선은 `총신대입구(이수)`, 7호선은 `이수`로 온다. 괄호를 지우면 우리 노드 이름(`총신대입구`, `이수`)과 맞는다.
- "역" 접미사는 `서울역`에만 있었다. 우리 이름도 `서울역`이다.
- 띄어쓰기 차이는 없었다.
- 노선 1~8 정차역 1,490개 중 그대로 일치 975개(65%), 괄호 제거 후 일치 359개(24%), 불일치 156개다. 불일치 중 지원 범위 안의 역은 `불암산` 8건뿐이다.

**4. 요금·단계 유형·방면**
- 요금은 경로 단위로만 있고 단계별 요금은 없다.
- SUBWAY 경로 61개는 모두 `fare.value`가 있다(예: 강남→홍대입구 1650).
- 버스가 포함된 경로 43개는 `value` 없이 `{min, max}`만 있다.
- 버스 구간은 `steps[].properties.type = BUS`로 구분된다. 경로 전체는 `routes[].properties.type`(`SUBWAY`/`BUS`/`BUS_AND_SUBWAY`)으로 구분된다.
- 방면(headsign)은 제공되지 않는다. `guidance`에도 `"(승차역 > 하차역)"`만 있다.

**5. 도보·지도 선·경로 분류**
- WALKING 단계 202개 모두 `distance`, `time`, `path.points`가 있다.
- 환승 도보는 `stops`가 같은 역 두 번(`[{"name":"성수"},{"name":"성수"}]`)이고 `guidance`는 `"성수성수역 환승"` 형식이다.
- 정류장까지 걷는 단계는 출구 번호가 guidance에 들어간다(예: `"... (13번 출구)"`).
- 역 좌표로 호출했기 때문에 출발지→역 도보 단계는 나오지 않았다. 실제 주소 좌표로 호출할 때는 따로 확인이 필요하다.
- 경로 분류는 `routes[].properties.type`과 최상위 `properties`의 경로 수로 알 수 있다.

**6. 응답 속도** (26회): 평균 552ms, 중앙값 516ms, 최소 191ms, 최대 1376ms. 최대값은 첫 호출이다. 6.1의 1회 타임아웃 3초 안에 들어온다.

**7. 매칭 불일치 목록** (매칭 순서: 그대로 → 괄호 제거 → "역" 제거)

| 구분 | 이름 | 비고 |
| --- | --- | --- |
| 지원 범위 안 | 4호선 `불암산` (8회) | 우리 데이터는 `당고개`(좌표 파일 2025-08-14 기준). 카카오 표기에 맞춰 `불암산`으로 개명 확정(V12, 별도 이슈) |

## 방향 판정 (6.1 "정차역 매핑과 방향")

- 같은 SUBWAY 단계 안의 연속 정차역 쌍으로 RIDE 간선을 찾는 방식이 그대로 동작했다.
- 2호선은 INNER 13단계, OUTER 12단계가 모두 나왔다. 그 밖에 UP 54, DOWN 81, LOOP 2단계가 나왔다.
- 한 단계 안에 방향이 둘인 경우는 `구산 → 응암 → 새절` 하나였다. 구산→응암은 LOOP, 응암→새절은 DOWN이다. 6호선 응암순환에서 본선으로 직통하는 실제 운행과 맞고, 명세처럼 쌍마다 방향을 정하면 문제없다.
- 지원 범위 밖 역만 있는 단계 6개는 방향을 정할 수 없었다(`supported: false` 대상).
- **카카오는 지선 분기점을 환승으로 나눈다.**
  - 건대입구→용답: `2호선 (건대입구 > 성수)` → WALKING `성수성수역 환승` → `2호선 (성수 > 용답)`
  - 둔촌동→길동: `5호선 (둔촌동 > 강동)` → `강동강동역 환승` → `5호선 (강동 > 길동)`
  - #56(성수·신도림·강동 환승 페널티)과 같은 판단이다. 신도림 신정지선 환승은 이번 구간(양천구청→신도림 직통 종점)에서 나오지 않았다.

## 6.1 규칙 변경 제안

1. **역명 정규화는 양쪽에 똑같이 적용한다.** 앞뒤 공백 제거 → 괄호와 그 안 제거 → "역" 접미사 제거. 카카오 이름에만 "역"을 지우면 `서울역`이 `서울`이 되어 우리 `서울역`과 맞지 않는다.
2. **4호선 `당고개`를 `불암산`으로 개명한다 (확정).** 카카오가 최신 역명 `불암산`으로 주고, 이번 호출에서 지원 범위 안 매칭 실패 8건이 모두 이 역이었다. 별칭으로 맞추지 않고 우리 데이터를 카카오 표기에 맞춘다. 개명은 Flyway V12로 별도 이슈에서 진행한다(적용된 V11과 원본 파일은 고치지 않는다). 개명 후에는 지원 범위 안 불일치가 없다.
3. **노선 매핑**: `vehicles[].name`이 `^[1-8]호선$`이면 그 line_code로 매핑한다. 그 밖은 `supported: false`다. 지선은 노선명이 아니라 정차역으로 정한다.
4. **경로 선택 (확정)**: 경로 단위 `routes[].properties.type = SUBWAY`인 경로만 쓴다. 단계에 `BUS`가 하나라도 있으면 그 경로는 제외한다. 지하철 경로가 하나도 없으면 내부 다익스트라(INTERNAL)로 폴백한다. 버스 구간은 응답에 노출하지 않는다.
   - 근거: 응답은 경로를 여러 개(이번 호출에서 최대 15개) 주고 BUS·혼합 경로가 섞여 있다. 첫 경로가 항상 지하철인 것도 아니다(둔촌동→길동은 첫 경로가 BUS 613초, 둘째가 SUBWAY 450초).
   - 이번 26회 호출은 모두 SUBWAY 경로가 하나 이상 있었고, SUBWAY 경로에는 BUS 단계가 없었다(WALKING은 환승 도보로 들어 있다).
5. **요금 (확정)**: `min`/`max`만 있는 경로는 모두 버스 포함 경로라 4번 규칙으로 제외되므로, 별도 처리 방법을 두지 않는다. 이번 호출의 SUBWAY 경로 61개는 모두 `fare.value`가 있었다. 다만 표본이 26구간이라 **지하철 전용 경로에 `fare.value`가 항상 있는지는 ⑨ 구현 초반에 다시 확인한다.**
6. **방면 정보는 기대하지 않는다.** 카카오는 headsign을 주지 않으므로 방향은 지금 명세대로 서버가 간선으로 정한다.

## 역 별칭 테이블 판단

DB 별칭 테이블은 지금 필요하지 않다.
- 지원 범위 안 불일치는 `불암산` 1건뿐이고, 이 역은 개명(V12)으로 해결한다. 나머지는 괄호 제거 규칙으로 해결된다.
- 우리 쪽 별칭(`서울`→`서울역`, `뚝섬유원지`→`자양`, 7호선 `총신대입구`→`이수`)은 시드 스크립트가 이미 노드 이름으로 바꿔 두었다. 카카오도 `서울역`, `이수`로 준다.
- 역이 개명되면 별칭을 두지 않고 우리 데이터를 카카오 최신 표기로 바꾼다(이번 `당고개`→`불암산`과 같은 방식). 개명은 드물어서 그때마다 새 마이그레이션으로 처리하면 된다.
- 사용자 검색에서 옛 이름(`당고개` 등)도 받을지는 #57(역 표시 이름·별칭 정책)에서 정한다.

이번 구간에 없어 확인하지 못한 것: 7호선 `자양`(카카오 표기가 `자양(뚝섬한강공원)`인지), 신도림 신정지선 환승 단계, 주소 좌표 출발 시 도보 단계.

## 쿼터 사용량과 호출 구간

총 **26회**(1단계 1회 + 2단계 25회), 재호출 0회, 오류 0회. 구간은 `scripts/kakao_probe/probe.py`의 `PAIRS`에 있다.

일일 쿼터 한도: **미확인(콘솔 확인 필요)**. 개발자 콘솔의 앱 쿼터 화면에서 대중교통 경로 조회의 일일 한도를 확인해 6.1 운영 기준에 적는다.

| 목적 | 구간 |
| --- | --- |
| 2호선 단일·내선/외선 | 강남→홍대입구, 홍대입구→강남 |
| 2호선 순환 닫힘 | 충정로→시청, 시청→충정로 |
| 성수지선·신정지선 | 건대입구→용답, 신설동→성수, 까치산→영등포구청, 양천구청→신도림 |
| 마천지선 | 마천→강동, 둔촌동→길동 |
| 응암순환 | 응암→연신내, 구산→새절 |
| 총신대입구(이수)·서울역 | 고속터미널→총신대입구(이수), 총신대입구(이수)→서울역, 서울역→청량리, 서울역→사당 |
| 환승 1회·2회 이상 | 잠실→고속터미널, 남태령→암사역사공원 |
| 장거리 | 방화→하남검단산, 장암→온수, 지축→오금, 암사역사공원→모란 |
