# 지하철 기준 데이터 적재 (#50)

V10 스키마(#48)에 1~8호선 노선·역·노드·간선을 넣는 시드 마이그레이션이다. `data/build_subway_seed.py`가 입력 파일에서 `V11__seed_subway_data.sql`을 생성한다. congestion_stats는 다루지 않는다.

| 테이블 | 건수 |
| --- | --- |
| subway_lines | 8 |
| stations | 240 (전부 `is_supported = true`) |
| station_lines | 277 |
| station_connections RIDE | 536 |
| station_connections TRANSFER | 78 |

## 매핑 규칙

**subway_lines**: line_code `1`~`8`, name `1호선`~`8호선`, sort_order 1~8, 색은 1 `#0052A4`, 2 `#00A84D`, 3 `#EF7C1C`, 4 `#00A5DE`, 5 `#996CAC`, 6 `#CD7C2F`, 7 `#747F00`, 8 `#E6186C`.

**역 이름**: 역명은 앞뒤 공백을 지운다. 좌표 파일 이름을 edges.csv 이름으로 바꾼다.
- 1·4호선 `서울` → `서울역`
- 7호선 `뚝섬유원지` → `자양`
- 7호선 `총신대입구` → `이수`

**stations**: 이름이 같은 노드는 노선이 달라도 한 역이다. 4호선 `총신대입구`와 7호선 `이수`는 한 역으로 합치고 이름은 `총신대입구(이수)`다. 합쳐진 역의 좌표는 번호가 가장 작은 노선의 좌표(보정 적용 후)를 쓴다(예: 서울역은 1호선, 총신대입구(이수)는 4호선 값). 240개 모두 `is_supported = true`다.

**station_lines**: (역, 노선)당 1행, station_code는 좌표 파일의 외부역코드(보정 파일에 코드가 있으면 그 값).
- MAIN은 진행 방향(DOWN, 2호선은 INNER) 간선을 따라 seq 1..n. 시작역은 들어오는 진행 방향 간선이 없는 역이고, 2호선은 시청이 1이다.
- 지선은 분기점 다음 역부터 그 branch_code로 seq 1..m. 분기점 역(성수, 신도림, 강동, 응암)은 MAIN 행 하나만 가진다.
  - 2호선 SEONGSU: 용답, 신답, 용두, 신설동
  - 2호선 SINJEONG: 도림천, 양천구청, 신정네거리, 까치산
  - 5호선 MACHEON: 둔촌동, 올림픽공원, 방이, 오금, 개롱, 거여, 마천
  - 6호선 EUNGAM_LOOP: 역촌, 불광, 독바위, 연신내, 구산 (응암에서 출발해 응암으로 닫히는 LOOP 6구간)

**RIDE**: edges.csv 536행 그대로. direction(UP/DOWN/INNER/OUTER/LOOP)도 그대로이고, from/to는 (노선, 역명)으로 노드를 찾는다.

**TRANSFER**: 환승 파일에서 호선과 환승노선이 모두 1~8호선인 행만 넣는다. 환승거리 → distance_m, 환승소요시간(mm:ss) → travel_seconds, direction은 null.

제외한 행 (스크립트가 모두 출력한다):
- 같은 노선 안 환승: 2호선 성수→2호선, 2호선 신도림→2호선, 5호선 강동→5호선
- 우리 데이터에 없는 1호선 역으로 가는 환승: 2호선 신도림, 4호선 창동, 5호선 신길, 7호선 도봉산·가산디지털단지·온수 → 1호선
- 1~8호선 밖 노선(9호선, 공항철도, 경의중앙선, 경춘선, 경원선, 국철, 수인분당선, 신분당선, 신림선, 우이신설선, 김포골드라인, 서해선, GTX-A): 59행

보충한 행: 2호선 까치산 → 5호선 까치산은 원본에 없어 반대 방향(5→2) 값 14초, 17m를 쓴다. 4호선 총신대입구 ↔ 7호선 이수는 원본 그대로 포함한다.

SQL은 id를 직접 넣지 않는다. station_lines는 같은 문장에서 새로 넣은 stations 행에만 연결하고(`insert ... returning`), 간선은 자연키 `(line_code, station_code)`로 노드를 찾는다.

## 검증 항목 (`SubwaySeedMigrationPostgresTest`)

Testcontainers PostgreSQL 16에서 SQL로 확인한다.
1. V10까지 적용된 DB에 V11 적용 성공, validate·재실행, 건수 8 / 240 / 277 / 536 / 78, congestion_stats 0건
2. 모든 노드에 RIDE 간선이 하나 이상 있음
3. LOOP를 뺀 모든 RIDE에 반대 방향 간선이 있음(INNER↔OUTER, UP↔DOWN). INNER/OUTER는 2호선 MAIN, LOOP는 6호선 응암순환에만 있음
4. 2호선 MAIN이 시청에서 43구간 뒤 시청으로 닫힘(충정로→시청 INNER, 시청→충정로 OUTER), 6호선 LOOP 6구간이 응암에서 닫힘
5. 노선·branch별 seq가 1부터 빈틈없이 이어짐, 지선 구성과 분기점 역의 MAIN 단일 행
6. RIDE+TRANSFER로 277개 노드가 모두 한 연결 요소
7. 같은 역의 모든 노선 쌍에 TRANSFER가 양방향으로 있음, TRANSFER는 같은 역·다른 노선·direction null
8. 같은 노선 안에 좌표가 같은 두 역이 없음, RIDE 구간의 하버사인 거리 h가 `0.45 × distance_m ≤ h ≤ 1.15 × distance_m + 300`
9. 위도 37.4~37.8, 경도 126.7~127.3, `is_supported` 전부 true, 역 이름 중복 없음, 합쳐진 역의 좌표 규칙
10. 보정 6건의 좌표, 암사역사공원 코드 2810·MAIN seq 1

## 갱신 방법

1. `data/raw/`의 입력 파일이나 `data/station_overrides.csv`를 고친다.
2. 새 마이그레이션 번호로 생성한다. 이미 적용된 V11은 고치지 않는다.
   ```
   python3 data/build_subway_seed.py src/main/resources/db/migration/V<새 번호>__<설명>.sql
   ```
   스크립트는 빈 테이블에 넣는 SQL을 만든다. 이미 데이터가 있는 DB를 갱신하려면 생성 결과를 `docs/subway-schema-48.md`의 적재 정책(역 삭제 금지, 자연키 upsert로 ID 유지)에 맞는 upsert·비활성화 SQL로 바꿔야 한다.
3. 스크립트 출력의 건수·제외·보충 목록을 이 문서와 대조하고, `./gradlew postgresTest`로 검증한다.

같은 입력이면 출력은 항상 같다(정렬 고정, 난수·시각 없음). Python 3.9 이상, 표준 라이브러리만 쓴다.
